# 虚拟文件系统（VFS）

## 作业目标

* 学会使用 STL 库
* 加深对于字符串处理的掌握
* 提高模拟水平，掌握基本的拆分功能、规划项目的能力
* 学会设计类型系统与类型检查规则
* 学会使用迭代器

## 作业要求

本作业要求实现一个**虚拟文件系统（VFS）**，模拟目录树、名字解析、文件类型系统，以及删除、统计等文件操作。**本次作业不会进行真实文件的操作，只是用终端模拟对文件的操作**

在该文件系统中，目录（directory）可以包含子目录和文件，文件（file）保存具体的内容。不同的目录下可以存在同名文件，互不干扰。

### 重要概念解释

* **根目录** `/` 是文件系统的顶层目录，程序开始时的当前目录（`cwd`）就是根目录。
* 每个目录包含若干子目录与文件，**同一目录下不允许重名**（文件与目录共用名字空间）。
* **直接子项**：直接属于当前目录的文件或子目录，不包括子目录的后代与父目录中的项。所有带名字参数的操作都只查找当前目录的直接子项；`cd` 接受路径参数，按路径逐段解析。
* `mkdir` / `create` 在当前目录创建直接子项；`rm` / `rm -r` 只删除当前目录的直接子项；`cd` 支持绝对路径与相对路径，`cd ..` 返回父目录。
* `cat` / `stat` / `append` / `read` / `write` 只查询当前目录的直接子项。目标不存在或类型不满足操作要求时，输出 `Invalid operation`。
* `rm -r` 找到当前目录的直接子目录后，递归删除它的整棵子树。

例如：当前目录 `/a` 下没有 `x.txt` 但根目录下有 `x.txt` 时，`cat x.txt` 与 `rm x.txt` 都输出 `Invalid operation`；返回根目录后，才能操作根目录的 `x.txt`。

`top` / `ls` / `undo` 不接受名字参数，不涉及名字解析；其中 `top` 只统计当前目录的直接子文件。

## 指令介绍

### `mkdir [name]`

在当前目录下创建一个子目录。

```
mkdir src
```

要求：

* 当前目录下已有同名项（文件或目录）时：`Invalid operation`。

### `cd [path]`

* `[path]` 以 `/` 开头时为**绝对路径**，从根目录开始解析；否则为**相对路径**，从当前目录开始解析。
* 路径以 `/` 分隔，`.` 表示所在目录，`..` 表示父目录，普通名字表示该目录的直接子目录。
* `cd /`：返回根目录；`cd ..`：返回父目录；`cd .`：留在当前目录。

```
cd src
cd ..
cd /a/b
cd ../b
cd ./b
cd /
```

要求：

* 路径格式保证正确，不出现连续 `/`；除根路径 `/` 外，不以 `/` 结尾。
* 从左到右逐段解析，每个普通名字都必须对应已存在的直接子目录。目标不存在或是文件时，输出`Invalid operation`。
* 解析路径时，任何一步尝试越过根目录，整条指令失败。解析路径时任一步失败，整条指令失败，视作未执行该指令，当前目录保持执行前的状态。

### `create [type] [name] [content]`

在当前目录下创建一个类型为 `[type]`、名为 `[name]` 的文件，内容为 `[content]`。

```
create txt main.cpp "int main()"
create md README.md "# title"
create bin data.bin "48 65 6C 6C 6F"
```

要求：

* 若当前目录下已有同名项，则输出`Invalid operation`。
* `[content]` 是以 `"` 开头并以 `"` 结尾的字符串常量（详见名字与字符串规则）。
* 三种类型都允许空内容，例如`create txt a.txt ""` 创建名为a.txt的空文本文件。
* `[type]` 为 `bin` 时，`[content]` 为大写十六进制字节序列；空串 `""` 表示空二进制文件。

### 文件格式

三种文件类型具有不同的内部格式：

* **`txt`（纯文本文件）**：内容以字符序列形式保存，是最基本的文本文件。
* **`md`（文档文件）**：内容同样是字符序列，但作为一种独立的文档类型存在，与 `txt` 是两种不同的类型。
* **`bin`（二进制文件）**：内容以**字节序列**形式保存，与文本文件的保存方式不同。创建时传入的 `[content]` 为大写十六进制字节序列；创建后可用 `read` / `write` 按字节操作。

相关规则：

* 文本操作（`append` / `cat`）只接受文本文件（`txt` / `md`）；`bin` 参与时输出 `Invalid operation`。
* 三种类型的区别通过 `stat` 输出的类型名体现。

### `append [name] [content]`

向文本文件追加内容。

```
create txt a.txt "hello"
append a.txt "world" // a的内容为"helloworld"
```

要求：

* `[name]` 必须是当前目录的**直接子项**，否则输出 `Invalid operation`。
* `[name]` 必须是文本文件（`txt` / `md`）。是目录或 `bin` 时，输出`Invalid operation`。
* 允许追加空串。

### `cat [name]`

输出文件的名字与内容。

```
cat a.txt
```

输出格式：`[name]:[content]`，例如 `a.txt:hello`。空文件输出 `[name]:`（冒号后无内容），与 `read` 的 `[length] = 0` 情形一致。

要求：

* `[name]` 必须是当前目录的**直接子项**，否则 `Invalid operation`。
* `[name]` 必须是文本文件（`txt` / `md`）。是目录或 `bin` 时：`Invalid operation`。

### `read [name] [offset] [length]`

输出 bin 文件从字节位置 `[offset]` 起的 `[length]` 个字节。

```
read a.bin 10 20
```

输出格式：`[name]:[hex]`，`hex` 为大写、单空格分隔的十六进制字节组，例如 `a.bin:01 02 03`。`[length]` 为 0 时输出 `[name]:`（冒号后无内容）。

要求：

* `[name]` 必须是当前目录的**直接子项**，且必须是 `bin` 文件。不存在、是目录或文本文件时：`Invalid operation`。
* `[offset] + [length]` 不得超过文件大小，否则输出 `Invalid operation`。

### `write [name] [offset] [hexdata]`

将 `[hexdata]` 表示的字节序列从字节位置 `[offset]` 起**覆盖**写入 bin 文件，不移动后续字节。例如原内容 `01 02 03 04`，执行

```
write a.bin 1 "FF FF"
```
后为 `01 FF FF 04`。

要求：

* `[name]` 必须是当前目录的**直接子项**，且必须是 `bin` 文件。文件不存在或是目录或是文本文件时，输出`Invalid operation`。
* `[hexdata]` 为非空的大写十六进制字节序列，以 `"` 开头并以 `"` 结尾的字符串常量形式给出。
* `[offset] + [hexdata] 字节数` 可以超过文件末尾：超出部分**扩展文件**。`[offset]` 大于原文件大小时，原末尾到 `[offset]` 之间的空缺字节补 `0`。

### `ls`

列出当前目录下的所有直接子项，按名字字典序每行一个，目录项带 `/` 后缀。若当前目录为空则无输出。

例如当前目录包含 `b.txt`、`a.txt` 与目录 `src`，输出：

```
a.txt
b.txt
src/
```

按字典序：`a.txt` < `b.txt` < `src`，**注意目录按不含 `/` 的名字参与排序。**

### `rm [name]`

删除当前目录下的一个直接子文件。

```
rm a.txt
```

要求：

* `[name]` 必须是当前目录的**直接子文件**，否则输出 `Invalid operation`。
* `[name]` 是文件时直接删除；是目录时输出 `Invalid operation`。

### `stat [name]`

输出指定名字（文件或目录）的类型与大小。

```
stat a.txt
```

输出格式：`[name]:[type]:[size]`。`type` 为 `txt` / `md` / `bin` / `dir` 之一；文件的 `size` 为内容**字节数**（`txt` / `md` 为字符串的字节长度，`bin` 为字节序列长度），目录的 `size` 固定为 `0`。

要求：

* `[name]` 必须是当前目录的**直接子项**，否则输出 `Invalid operation`。

### `top [k]`

输出**当前目录内**大小最大的 `k` 个文件。

```
top 3
```

输出格式：每行 `[name]:[size]`，按 `size` 降序排列；`size` 相同时按名字字典序排列。

要求：

* 只统计当前目录的**直接子文件**（不含子目录与其他目录内文件）。
* `k` 保证为正整数；`k` 大于文件总数时全部输出；没有文件时无输出。

### `undo`

`undo` 撤销最近一次成功执行的可撤销操作，使文件系统恢复到执行该操作之前的状态。

```
undo
```

要求：

* 可撤销操作包括 `mkdir` / `create` / `append` / `cd` / `write` / `rm`。
* 只有成功执行的可撤销操作会产生记录。即使内容未变化（如 `append` 空串、`write` 写入相同字节），成功执行仍产生一条记录；查询操作与输出 `Invalid operation` 的操作不产生记录。
* `undo` 按**后进先出**顺序处理记录，本身不额外产生操作记录，可以连续执行。
* 没有可撤销记录时，`undo` 输出 `Invalid operation`。

## 名字与字符串规则

本节定义输入的格式规则。**输入保证格式正确**，程序中不需要检查格式错误，但解析需要按这些规则进行。

* **名字（name）**：非空，不含 `/`，保证为ASCII字符，不含空白字符（空格、制表符等），不含 `"`，不是 `.` 或 `..`，大小不超过 20 个字节。除 `.` 与 `..` 外，以 `.` 开头的名字（如 `.gitignore`）是合法且普通的名字。
* **路径（path，仅用于 `cd`）**：非空，不含空白字符或 `"`；可为根路径 `/`，也可由可选的开头 `/` 和若干以单个 `/` 分隔的非空路径段组成。路径段为 `.`、`..` 或符合名字规则的普通名字。保证没有连续 `/`，除根路径 `/` 外没有末尾 `/`。
* **无隐藏文件规则**：本文件系统不区分隐藏文件，名字是否以 `.` 开头不产生任何特殊语义，`ls` 与 `tree` 一律输出所有子项。
* **字符串常量（content）**：以 `"` 开头并以 `"` 结尾，中间为任意内容（可含空格），不支持转义字符，中间不能出现 `"`。解析时取第一个 `"` 与最后一个 `"` 之间的内容。
* **十六进制字节序列（`bin` 的 content）**：由单个空格分隔的若干**两位十六进制数字**组成，仅含 `0-9`、`A-F`；不含小写字母与多余空格。`create` 允许空串（空文件）；`write` 的序列非空。

## 输入格式

第一行一个整数 `n`，表示指令条数。之后共 `n` 行，每行一条指令。

保证：

* 指令的关键字必然合法，**每行参数数量保证正确**。
* 名字、`cd` 的路径、字符串常量、十六进制字节序列均符合"名字与字符串规则"；`[type]` 必为 `txt` / `md` / `bin` 之一。
* `top` 的 `k` 为正整数；`read` / `write` 的数字参数为非负整数。

**输入格式保证正确**指每行都符合对应指令的参数写法与取值规则：指令条数、参数个数、名字、路径、引号、类型、数字范围，以及 `create bin` 的 `[content]` 和 `write` 的 `[hexdata]` 都满足上述格式要求。即使目标文件不存在、已重名或类型不对，也不会出现格式错误的参数；程序不需要处理格式错误，格式错误的输入没有规定输出。

**不保证语义正确**指格式正确的指令执行时仍可能因文件系统的当前状态或操作要求而失败：重复创建同名项、名字不存在或不是当前目录的直接子项、对不符合操作要求的文件类型执行操作（如对 `bin` 文件执行 `cat`、对文本文件执行 `read`）、读取越界、`cd` 路径中的目录不存在、遇到文件或尝试越过根目录、对目录执行 `rm`、`undo` 无记录等。这类错误按对应指令规则输出 `Invalid operation`，并继续处理后续指令。

例如 `create bin dd "41"` 是格式正确的创建指令；若随后执行 `cat dd`，由于 `cat` 只接受文本文件，属于语义上的类型不匹配，应输出 `Invalid operation`。而 `create bin dd "same"` 的内容不是十六进制字节序列，属于**输入格式错误**，不会作为测试输入；`create txt dd "same"` 中的普通文本内容则是合法的。

数据范围：`n <= 2e5`，根目录深度为0，所有目录深度≤99，`cd` 路径段个数不超过 `100`；`read` / `write` 的 `offset`、`read`的`length` 不超过 `1e5`，`top` 的 `k` 不超过 `1000`。每个测试点中 `top` 指令最多出现 1000 次。每条指令中的字符串常量，不含两端引号，大小不超过 48KiB。

测试数据保证：任意时刻，任一文件的内容大小不超过 256KiB。

## 输出格式

* `cat`：输出 `[name]:[content]`。
* `read`：输出 `[name]:[hex]`，`hex` 为大写、单空格分隔的十六进制字节组。
* `stat`：输出 `[name]:[type]:[size]`。
* `top`：输出 `[name]:[size]`，`size` 降序、同 `size` 按名字字典序。
* `ls`：名字字典序，目录带 `/`。
* 任何语义上非法的操作：输出 `Invalid operation` 并换行。非法操作不影响程序继续执行。

## Bonus 说明

### `redo`

重做最近一次被 `undo` 撤销的操作，使文件系统恢复到执行该操作之后的状态。`redo` 不接受名字参数，不涉及名字解析。

```
redo
```

要求：

* 可重做的操作包括主体中的 `mkdir` / `create` / `append` / `cd` / `write` / `rm`，以及 Bonus 中的 `rm -r`。
* 成功的 `undo` 将最近一条可撤销记录移入可重做记录；成功的 `redo` 将最近一条可重做记录移回可撤销记录。
* `undo` 与 `redo` 均按后进先出顺序处理各自的记录，两条指令本身不额外产生操作记录，均可连续执行。
* 任何成功执行的可撤销操作都会清空可重做记录，即使内容或当前目录未变化；查询操作与输出 `Invalid operation` 的操作不清空。
* 没有可重做记录时，`redo` 输出 `Invalid operation`。

### `rm -r [name]`

删除当前目录下的一个直接子项。文件直接删除；目录**递归删除**（连同其整棵子树）。

```
rm -r src
```

要求：

* `[name]` 必须是当前目录的**直接子项**，否则输出 `Invalid operation`。
* 文件、空目录和非空目录均可删除。
* 成功的操作产生可撤销记录，`undo` 可以完整恢复被删除的文件或整棵子树，`redo` 可以再次删除。

### `tree`

从当前目录开始，以缩进树形式输出整棵子树，不接受名字参数，不涉及名字解析，不改变文件系统状态。

```
tree
```

输出要求：

* 首行为当前目录名（路径最后一段）加 `/`（根目录为 `/`），空目录也输出首行。
* 每行一个节点；同一目录下按名字字典序排列（目录按不含 `/` 的名字参与排序，与 `ls` 一致），目录带 `/`。
* 本文件系统**没有隐藏文件规则**：以 `.` 开头的名字与普通名字完全等价，`ls` 与 `tree` 都一律输出，不做任何过滤。
* 缩进使用 UTF-8 制图字符：非最后一项前缀 `├── `，最后一项前缀 `└── `；进入子目录后，其子项前缀分别延续 `│   ` 与 `    `（四个空格）。
* 在代码中输出制图字符应查阅 UTF-8 文档，通过输出对应字节编码来完成制图字符的输出，不能直接复制粘贴本文档中的制图字符。我们会在Code Review中检查你的代码是否做到这一点。
* 每个测试点中 `tree`至多出现50次。

完整示例（执行到 `tree` 时当前目录为 `/a`）：

输入：

```
11
mkdir a
cd a
create txt f "x"
mkdir b
cd b
create txt g "y"
cd ..
rm -r b
undo
redo
tree
```

输出：

```
a/
└── f
```

## 本地测试脚本

仓库提供 `test_core.sh`（主体）和 `test_bonus.sh`（Bonus）。在仓库根目录的 Bash 终端中运行，需要安装 `g++` 或 `clang++`。

脚本会以 `-std=c++17 -O2` 编译指定源码，运行对应的公开样例，并与同名 `.out` 文件比较，显示每个用例的 `PASS` / `FAIL`、耗时和汇总。**默认每个用例的时限为 1000ms**。

```bash
# 测试自己的主体 / Bonus 实现（将文件名替换为自己的源码）
./test_core.sh --src main.cpp
./test_bonus.sh --src main_bonus.cpp

# 只运行名字包含 public03 的用例，并在失败时显示完整差异
./test_core.sh --src main.cpp public03 -v

# 使用已经编译好的程序，跳过编译
./test_core.sh --bin ./main
```

不指定 `--src` 时，两个脚本默认使用 `vfs_core.cpp` / `vfs_bonus.cpp`；测试数据分别来自 `data_core_public/` / `data_bonus_public/`。常用选项如下（两份脚本相同）：

| 参数         | 说明                                                       |
| ------------ | ---------------------------------------------------------- |
| `--src FILE` | 指定待测试的 C++ 源码                                      |
| `--bin FILE` | 指定已有可执行文件，跳过编译                               |
| `--list`     | 列出用例，不运行测试                                       |
| `-v`         | 失败时显示完整输出差异和标准错误                           |
| `-t SEC`     | 调整本地单个用例的时限，单位为秒；默认 `1`，`0` 表示不限时 |
| `-h`         | 查看完整帮助                                               |

位置参数按用例名子串筛选，可指定多个。脚本退出码为：`0` 表示全部通过，`1` 表示测试未通过，`2` 表示参数、编译或环境错误。
